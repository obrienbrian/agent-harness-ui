00Assumptions, context, and the calls I made
Context I read

docs/UI-CONTRACT.md v1 and harness_ui/server.py from obrienbrian/agent-harness-ui@master. Every field rendered below exists in the frozen payload, except the one additive field flagged in 1f.

The current page's own contract section asks for the Discord look and a legend chart. This revamp overrides both; the data expectations (poll cadence, redaction, phone-first stacking) are kept exactly.

Layout: I chose variant A

Graph as a full-width band above the feed, collapsible to a 40px strip. Two reasons: the phone layout already puts a graph strip above the feed, so A makes desktop and phone structurally the same design at two densities rather than two different designs. And the S-curve topology needs horizontal room — at 320px the rail forces workers into a cramped stack, at 800px six workers breathe.

Variant B is drawn in full at 1c so you can compare. The right rail is better spent on insights, which read fine narrow.

Naming, per your answer

Session pill and orchestrator node lead with orchestrator.name ("Orchestrator", user-set) and caption the persona: Orchestrator · fable · claude · high. Workers still lead with persona, since they have no custom name.

The sample content in §10 says "Fable" for the orchestrator. I render it as Fable in the feed and graph because that fixture's name is set to the persona — the rule is "custom name wins", and here it happens to match.

Open risks

Comets are offset-path on a div. Safari 16+ and Chrome are fine; the fallback is an SVG <animateMotion> on the same path string, noted in 1i.

No Stop control anywhere, since the API cannot honour one. The busy composer says what it can: who is working and for how long.
